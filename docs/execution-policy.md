# Ariadne 작업 실행 정책

> 목표 정책은 확정했다. 공개본은 문맥·연결 기반 요소까지이며 공통 CLI·자동 실행·복구·완료 봉인은 제품 적용 미완료다. 이번 보완도 설계이며 실행 기능을 활성화하지 않는다.

이 정책은 사용자가 연결한 코딩 도구 하나 또는 여러 개로 같은 작업을 이어 가는 기준이다.
실행기는 Codex·Claude Code·Gemini 같은 코딩 에이전트 연결이나 승인된 모델 API 연결을 뜻한다.
작업은 하나의 목표와 완료 기준을 가진 단위이며, 구현·검토·재시도는 그 작업에 속한 실행이다.

## 어디에서 작업을 시작하는가

1. **등록하고 허용한 실행기 하나만으로도 작업을 진행할 수 있다.**

   여러 제품에 모두 로그인할 필요는 없다. 로그인·등록만으로 자동 실행이나 새로운 과금이 승인되지는 않는다.
   실제 연결과 필요한 권한 제한을 검증하지 못한 실행기는 자동 실행에 사용하지 않는다.

2. **기존 코딩 도구 화면을 유지하고, 공통 CLI에서 작업 목록·재개·중지·실행기 지정을 제공한다.**

   모델 API만 사용하는 구성은 공통 CLI가 시작점이다. 웹 대시보드는 첫 제공 범위에 포함하지 않는다.
   기존 화면의 진행 중 대화를 임의로 제어하거나 모든 메시지를 자동으로 수집하지 않는다.

## 새 요청이나 외부 이벤트가 들어오면

1. **첫 자동 실행 범위는 사용자가 맡기고 승인한 작업의 후속 처리다.**

   후속 요청이 원래 범위와 현재 승인 안에 있으면 같은 작업으로 이어 간다.
   새 목표·권한·데이터 반출 범위가 필요하면 이를 확인하기 전 해당 확장 작업을 시작하지 않는다.

2. **새 CI 실패나 리뷰 이벤트는 먼저 처리 후보로 기록한다.**

   후보 기록은 실행·모델 호출·외부 발송 승인이 아니다. 새 작업 자동 시작은 프로젝트별 조건과 승인을 별도로 활성화한 경우에만 가능하다.
   관련 댓글을 참고하는 것과 그 작성자에게 실행 승인 권한을 부여하는 것도 구분한다.

## 실행기를 고르거나 바꾸면

1. **사용자가 특정 실행기를 지정하면 그 지정이 자동 배정보다 우선한다.**

   지정한 실행기를 사용할 수 없으면 이유를 알리고 대기한다. 허용된 다른 도구가 있어도 임의로 대체하지 않는다.

2. **자동 배정은 승인 예산 안에서 완료 품질을 먼저 만족하는 후보를 고른다.**

   역할별로 검증한 기능·품질과 현재 가용성을 사용한다. 공급자 이름·모델 크기·가격만으로 품질을 추정하지 않는다.
   품질과 필수 기능이 충족된 후보 사이에서 사용자 우선순위·속도·사용량을 비교한다. 비교 근거가 없으면 이를 지어내지 않는다.

3. **자동 배정한 실행기가 제한·장애로 진행할 수 없으면, 기존 실행의 종료와 효과를 확인한 뒤 허용된 다른 실행기로 넘길 수 있다.**

   동일 작업의 남은 예산·현재 승인·데이터 범위를 유지한다. 승인하지 않은 유료 경로·계정·공급자로는 자동 전환하지 않는다.
   이전 실행의 결과가 불명확하면 재조회하고 전환은 대기한다. 사용자가 명시적으로 전환을 요청한 경우에도 같은 확인이 필요하다.

4. **허용한 자료만 해당 실행기로 전달한다.**

   요약뿐 아니라 완료 기준·댓글·도구 결과·오류·인수인계 자료 전체에 같은 반출 정책을 적용한다.
   인증 정보·다른 프로젝트 자료를 전달하지 않으며, 필수 의미를 보존할 수 없는 정제나 크기 초과는 자료를 몰래 줄이지 않고 전달을 거절한다.
   모델의 제안·등록 정보·대화 속 지시가 새로운 실행 권한이 되지 않는다.
   Git 게시 전에도 실제 추적 파일과 게시 이력을 확인한다. ignore 설정이나 테스트용 값이라는 표기만으로 민감정보가 없다고 판단하지 않는다.

예를 들어 자동 배정된 Codex가 한도에 도달했고 종료와 수정 결과가 확인됐다면, 허용된 Claude Code가 같은 작업을 이어 갈 수 있다.
반대로 사용자가 Codex를 지정했다면 사용자 변경 요청 전까지 기다린다. 두 경우 모두 작업 예산을 새로 부여하지 않는다.

## Mac이나 Ariadne를 다시 켜면

1. **기존 실행·현재 소스·승인·남은 예산이 확인된 미완료 작업만 자동 재개한다.**

   아직 살아 있는 실행은 같은 실행을 다시 관측한다. 새 실행이 필요한 경우에도 기존 실행 종료·효과 확인과 작업 공간 소유권 이전이 먼저다.
   기록이 남았다는 이유만으로 중복 실행하거나 현재 파일을 과거 상태로 되돌리지 않는다.

2. **사용자 중지·취소·승인 대기·결과 불명확 상태는 자동 재개 대상에서 제외한다.**

   결과 불명확 상태는 기존 실행을 먼저 확인한다. 사용자가 중지한 작업은 명시적으로 재개를 요청해야 한다.
   승인이나 예산이 만료됐으면 재확인하며, 재시작이 기존 승인을 되살리거나 예산을 초기화하지 않는다.

3. **여러 복구가 겹쳐도 실행 관리 담당은 하나만 둔다.**

   이전 담당의 응답 지연이나 죽은 프로세스 번호만 보고 소유권을 빼앗지 않는다.
   복구를 먼저 시작했다는 이유로 다른 담당이 새로 확보한 잠금·연결을 지우지 않는다. 소유권과 이전 실행이 확인되기 전에는 관측만 한다.

## 여러 실행을 함께 진행하면

1. **초기 동시 실행 상한은 전체 2개이며, 같은 작업 공간에는 쓰기 담당 하나만 둔다.**

   독립 작업이나 고정된 소스의 검토는 이 상한 안에서 병렬 진행할 수 있다. 자식 실행·독립 검토도 같은 상한을 사용한다.
   2개는 성능 측정 결과가 아닌 첫 운영 기본값이다. 성능 검증 없이 처리량 보장으로 해석하지 않는다.

2. **실행 종료나 효과가 불명확하면 해당 슬롯과 쓰기 소유권을 재발급하지 않는다.**

   프로세스 응답이 없거나 취소를 요청했다는 이유로 자리를 비우지 않는다. 확인이 끝날 때까지 대기 사유를 남긴다.
   한도가 찼으면 추가 실행을 대기시키며 내부 자식 실행으로 한도를 우회하지 않는다.

## 작업 예산과 승인을 나누면

1. **작업 전체에 실행기·행동 범위·한도를 한 번 승인하고, 그 안의 구현·검토·재시도·허용된 전환은 추가 확인 없이 진행한다.**

   시간·실행 횟수·동시성·관측 가능한 사용량을 함께 제한한다. 모든 역할과 자식 실행은 같은 작업 예산을 나눠 쓴다.
   재개·전환·새 실행 ID가 새 예산을 만들지 않는다. 필요한 한도가 정해지지 않았으면 자동 실행을 시작하지 않는다.

2. **예산 초과·새 유료 경로·권한 확대가 필요하면 추가 실행과 후속 효과를 차단하고 확인을 요청한다.**

   미리 승인한 API 경로의 추가 호출은 승인된 예산 안에서만 가능하다. 등록·로그인이나 구독 한도 소진이 새 유료 실행 승인을 대신하지 않는다.
   push·merge·배포·외부 발송·credential 변경·복구 어려운 삭제에는 여전히 별도 명시 승인이 필요하다.
   진행 중 실행에는 중지를 요청하고 실제 종료·효과를 확인한다. 요청만으로 종료됐거나 이미 접수된 효과가 취소됐다고 보고하지 않는다.

3. **실제 사용량을 확인할 수 없는 부분은 불명확한 값으로 남긴다.**

   알 수 없는 사용량을 0으로 처리하거나 알 수 없는 금액 상한을 보장하지 않는다.
   금액의 엄격한 상한이 필요한 실행은 공급자 측 한도나 보수적 사전 예약을 검증하지 못하면 시작하지 않는다.
   실행 중지는 이미 접수된 호출의 비용 취소를 뜻하지 않는다.

## 작업이 끝나거나 멈추면

1. **실행 성공과 작업 완료를 구분한다.**

   작업은 현재 완료 기준별 근거·필수 검증·소스 상태·미해결 실행·정리가 확인된 뒤에만 완료한다.
   모델의 완료 문장·프로세스 종료 코드·다른 도구의 요약 하나만으로 완료를 확정하지 않는다.
   완료 기준과 별도로 지정한 필수 검사를 모두 확인한다. 최신 검사가 진행 중·실패·결과 불명확이면 과거 성공으로 대신하지 않는다.
   완료 뒤 새 검사를 요청하면 과거 기록과 실행 종결 상태를 보존하되 현재 근거의 유효성을 별도로 판단한다. 재검사 실패를 현재 검증 완료로 표시하지 않으며 새 이벤트·재시작이 작업을 자동 재개하지 않는다. 새 수정 실행은 명시한 새 요구 revision과 승인으로 진행한다.

2. **진행이 멈추면 현재 상태와 근거·남은 행동을 보존한다.**

   같은 원인에 새 근거 없는 재시도를 반복하지 않는다. 관련 입력·소스·설정 변경과 새 관측을 기록하며 요약·실행 번호·재시작만으로 새 시도로 인정하지 않는다.
   일시 오류의 제한된 재조회와 결과 불명확 작업의 재실행을 구분한다. 잘못된 테스트를 고칠 수 있지만 통과를 위한 검사 약화는 허용하지 않는다.
   작업 소유 임시 자원만 정리하고 사용자 변경·공유 자원은 보존한다.
   다른 실행기로 넘길 때도 목표·결정·검증·진행 handle을 전달하고 원본 credential이나 비공개 내부 상태를 복사하지 않는다.

이 자동 실행 정책은 기능을 도입하고 현재 승인을 확인한 작업에 적용한다. 기존 기록을 일괄 재실행·재인증하거나 수정하지 않는다.
공통 규칙과 수동 작업 절차의 현재 동작은 기존 안내를 따른다. 이 정책의 확정 자체가 기능 활성화나 실제 유료 실행 승인은 아니다.

구현 책임과 검증 시나리오는 [통합 실행 설계](unified-execution-design.md)에서 확인한다.
